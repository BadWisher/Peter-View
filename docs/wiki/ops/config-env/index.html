    Переменные окружения¶

    Эта страница справочник конфигурации развертывания. Она нужна администратору, который настраивает сервис на сервере: здесь перечислены все переменные, их назначение, значения по умолчанию и место, где их задавать. Состав контейнеров описан на странице Стек контейнеров, практический запуск на странице Развертывание, настройки, видимые в интерфейсе, на странице Языковая модель.

    Источник значений и приоритет¶

    Файл .env лежит рядом с docker-compose.yml и подключается к контейнеру backend строкой env_file. Backend читает переменные через стандартный механизм Python-окружения. Часть значений переопределяется блоком environment: того же compose-файла: по правилам compose блок environment: важнее .env, поэтому четыре переменные из него изменить через .env нельзя. Об этом написано в разделе Переменные, зашитые в compose-файл.

    Настройки языковой модели и эмбеддингов дублируются в интерфейсе. После первого сохранения через экран Настройки значения живут в файле data/llm_settings.json (права 0600) и имеют приоритет над .env. То есть интерфейс перекрывает .env, а не наоборот.

    Истинные значения булевых переменных одинаковы для всех флагов: 1, true, yes, on, да. Регистр не учитывается.

    Порт, cookie и доступность Swagger¶

    Переменные базового доступа к сервису собраны в таблице.

    Переменная По умолчанию Назначение
    PROOFREADER_PORT 3080 хостовый порт nginx, единственная точка доступа наружу
    PROOFREADER_COOKIE_SECURE false флаг Secure на сессионной cookie; ставят true за HTTPS
    PROOFREADER_CORS_ORIGINS пусто список origin через запятую для кросс-доменных запросов с учетными данными; пусто означает same-origin
    PROOFREADER_DOCS false включает Swagger на путях /api/docs, /api/redoc и /api/openapi.json
    JIRA_BASE_URL пусто ссылка на Jira, показывается в ответе сессии и в разделе Документы

    Переменная PROOFREADER_DOCS задана и в .env, и в блоке environment: compose-файла со значением false. Через .env Swagger не включить, потому что блок environment: перекрывает его. Swagger включают правкой compose-файла. Когда Swagger выключен, nginx по-прежнему проксирует эти пути, но приложение отвечает кодом 404.

    Флаги дополнительных разделов¶

    Ядро сервиса (вычитка, гайды, история, аналитика) отключить нельзя. Опциональные разделы выключены по умолчанию и включаются переменными из таблицы.

    Переменная Раздел Префикс API
    FEATURE_DOCUMENTS Документы /api/repo
    FEATURE_API Спецификации API /api/api-spec*
    FEATURE_WATCH Наблюдение за страницами /api/watch
    FEATURE_SCREENSHOTS Редактор скриншотов /api/screenshot-templates

    Выключенный раздел недоступен и в интерфейсе, и по HTTP: запросы к его эндпоинтам возвращают 404.

    Сеть и защита от SSRF¶

    Настройки сетевой защиты перечислены в таблице.

    Переменная По умолчанию Назначение
    PROOFREADER_SSRF_ALLOW_PRIVATE true разрешать пользовательским адресам приватные сети (интранет); на публичном хосте ставят false
    PROOFREADER_MAX_FETCH_BYTES 10485760 (10 МиБ) потолок размера скачанной страницы
    PROOFREADER_MAX_REDIRECTS 5 сколько редиректов проходится при загрузке адреса; каждый шаг перепроверяется на SSRF
    PROOFREADER_SECRET пусто (см. текст) ключ обфускации хранимых паролей и снимков раздела Наблюдение

    Если PROOFREADER_SECRET не задан, сервис один раз генерирует случайный ключ и кладет его в файл data/watch.db.key с правами 0600. Свой ключ задают, когда томов несколько или когда нужен контроль над ротацией. Подробно механизм описан на странице Механизмы защиты.

    Защита загрузки DOCX от zip-бомб¶

    Три лимита защищают распаковку DOCX от zip-бомб.

    Переменная По умолчанию
    DOCX_MAX_UNCOMPRESSED_BYTES 314572800 (300 МиБ)
    DOCX_MAX_COMPRESSION_RATIO 200
    DOCX_MAX_ENTRIES 2000

    Модель и эмбеддинги¶

    Эти переменные читаются из окружения как начальные значения, но после первого сохранения через экран Настройки переезжают в data/llm_settings.json и подчиняются интерфейсу. Пустой адрес модели означает, что полная проверка выключена.

    Переменная Дефолт в коде Дефолт в .env.example Поле интерфейса
    LLM_BASE_URL пусто пусто Адрес API
    LLM_API_KEY пусто пусто API-ключ (секрет)
    LLM_MODEL пусто пусто Модель
    LLM_TEMPERATURE 0.0 0 Температура
    LLM_CONCURRENCY 5 4 Параллельность
    LLM_TIMEOUT 120.0 180 Тайм-аут
    LLM_JSON_MODE true true JSON-режим
    LLM_REASONING_EFFORT пусто low Усилие рассуждения
    EMBEDDING_BASE_URL пусто пусто Адрес эмбеддингов
    EMBEDDING_API_KEY пусто пусто Ключ эмбеддингов (секрет)
    EMBEDDING_MODEL пусто пусто Модель эмбеддингов

    Важно расхождение дефолтов. Значения LLM_CONCURRENCY и LLM_TIMEOUT в коде (5 и 120.0) отличаются от значений .env.example (4 и 180). Реальное начальное значение то, которое задано в .env; если переменная там не задана, применяется дефолт кода. Держите .env и ожидания команды согласованными.

    Конвейер проверки моделью¶

    Переменные конвейера и их дефолты приведены в таблице.

    Переменная По умолчанию Назначение
    PIPELINE_VERSION v2 версия конвейера (v1 или v2); v1 оставлен для откатов
    PIPELINE_SHADOW false параллельно прогонять v1 и v2 для сравнения метрик
    PIPELINE_V2_STAGES evidence,language,guide,structure,terminology,consistency,lexicon,verifier включенные стадии v2 списком через запятую
    PIPELINE_V2_PASS_TIMEOUT 360 тайм-аут одного прохода воркера в секундах
    PIPELINE_V2_PASS_RETRIES 2 число повторов прохода при тайм-ауте или сетевой ошибке
    RAG_CONFIG_VERSION v1 в коде, v2 в .env.example версия схемы кэша RAG в клиенте эмбеддингов
    PROMPT_VERSION v1 набор Jinja2-промптов для воркеров
    LLM_JOB_TIMEOUT 900 потолок жизни задачи в секундах (только из окружения)
    LLM_STREAM_BLOCK_CAP 20000 число знаков в одном блоке стрима (только из окружения)

    Эмбеддинги и извлечение гайда¶

    Эти четыре переменные настраивают эмбеддинги и извлечение гайда.

    Переменная По умолчанию Назначение
    EMBED_TIMEOUT 20 тайм-аут запроса эмбеддингов в секундах
    EMBED_BATCH_SIZE 90 размер батча эмбеддингов
    STYLEGUIDE_EXTRACT_TIMEOUT 900 потолок извлечения гайда из документа в секундах
    STYLEGUIDE_EXTRACT_CONCURRENCY 3 параллельность обработки чанков при извлечении

    Эти переменные в интерфейсе не продублированы и задаются только через .env.

    Вход через OIDC¶

    OIDC-настройки читаются прямо из окружения и в интерфейсе не редактируются. Полную настройку описывает страница Вход через OIDC.

    Переменная По умолчанию Назначение
    OIDC_ISSUER пусто адрес провайдера; пусто означает только локальный вход
    OIDC_CLIENT_ID пусто идентификатор клиента
    OIDC_CLIENT_SECRET пусто секрет клиента
    OIDC_REDIRECT_URI пусто адрес возврата, должен совпасть с настройкой у провайдера
    OIDC_ADMIN_GROUPS пусто имена групп, участники которых получают роль администратора

    Переменные, зашитые в compose-файл¶

    Эти четыре значения стоят в блоке environment: сервиса backend в docker-compose.yml и перекрывают .env. Искать их в .env бессмысленно.

    Переменная Значение
    LANGUAGETOOL_URL http://languagetool:8010/v2/check
    STYLEGUIDE_PATH /app/styleguide/rules.yaml
    STYLEGUIDE_STORE_DIR /app/data/styleguides
    PROOFREADER_DOCS false

    Переменные уровня compose, не читаемые backend-приложением¶

    Эти переменные подставляет compose при сборке и запуске, backend их не читает. PROOFREADER_CORP_PROXY включает overlay корпоративного прокси, три переменные CORP_PROXY_* настраивают мост, а GHCR_REPOSITORY и IMAGE_SHA задают образы в production-overlay.

    Переменная Значение по умолчанию Назначение
    PROOFREADER_CORP_PROXY false включает overlay docker-compose.corp-proxy.yml
    CORP_PROXY_UPSTREAM 127.0.0.1:3128 адрес корпоративного прокси-сервера
    CORP_PROXY_BRIDGE_PORT 3128 порт listening моста socat
    CORP_PROXY_BRIDGE_BIND 172.17.0.1 адрес, на котором мост слушает
    GHCR_REPOSITORY обязателен путь к репозиторию образов в GHCR (production-overlay)
    IMAGE_SHA обязателен тег образа (production-overlay)

    Связанные разделы¶

    Страницы, продолжающие тему конфигурации.

    • Стек контейнеров описывает compose-файлы, образы и зашитый блок environment:.
    • Развертывание показывает, как задать .env и запустить стек.
    • TLS и обратный прокси объясняет, где применяется PROOFREADER_COOKIE_SECURE.
    • Жесткая настройка для публичного хоста рекомендует значения для публичного доступа.
    • Резервное копирование и восстановление описывает BACKUP_DIR и BACKUP_KEEP.
    • Вход через OIDC подробно разбирает переменные OIDC.
