    Проектные решения¶

    Страница отвечает на «почему сделано так, а не иначе». Каждое решение в трёх частях: контекст, выбор, цена, которую за него платят. Формально это ADR-лог, только живёт он одной страницей, потому что решений набралось на раздел, а не на книгу. Формулировки честные: у части решений цена известна заранее, и она записана здесь, а не обнаружена в issue.

    Один хост, три контейнера, один процесс¶

    Контекст. Сервис ставится внутри команды, не в облаке с балансировщиком. Аудитория десятки авторов, пик нагрузки длинная вычитка большого документа.

    Решение. compose-стек: nginx со статикой, FastAPI одним процессом asyncio, LanguageTool на JVM. Наружу публикуется только порт nginx. Никакого оркестрации, шардинга и реплик.

    Цена. Нет горизонтального масштабирования и нет zero-downtime обновлений: рестарт рвёт SSE-стримы и сбрасывает незавершённые задачи (они честно помечаются ошибкой «Прервано рестартом сервера»). При росте аудитории первым узким местом станет одинокий uvicorn, и тогда понадобятся как минимум внешние сессии и очередь задач. Пока это осознанная отсрочка: вся вычислительно тяжёлая работа (модель) вообще снаружи процесса.

    Сессии в памяти процесса¶

    Контекст. Нужна авторизация по cookie. Классика «Redis или БД для сессий» тянет ещё один разворачиваемый компонент.

    Решение. Словарь SESSIONS в памяти, токен secrets.token_urlsafe(32), TTL 12 часов со скольжением. Побочный выигрыш: logout «всех» и сброс чужих сессий при смене пароля это drop_sessions(username), пара строк, без внешних вызовов.

    Цена. Рестарт разлогинивает всех пользователей (посреди длинной проверки неприятно, но проверка переживает рестарт: job в jobs.db, результат заберётся заново). Rate-лимиты логина живут в той же памяти и обнуляются рестартом, поэтому брутфорс через рестарты сервисов чуть дешевле атакующему. Для деплоя за TLS в одной инстанции ни то ни другое не критично.

    CSRF без токенов¶

    Контекст. Cookie-сессия обязана чем-то защищаться от межсайтовых запросов. Варианты: CSRF-токен в каждой форме, Double Submit Cookie, SameSite + проверка происхождения.

    Решение. SameSite=Lax на cookie плюс middleware, который для не-безопасных методов сверяет хост заголовков Origin/Referer с Host запроса. Токенов нет ни в HTML, ни в JS.

    Почему этого хватает. Фронт ходит строго same-origin через nginx (CORS по умолчанию пуст), так что легитимный запрос всегда приходит с нашим Origin. Из чужого сайта браузер либо не отправит cookie (Lax на POST), либо отправит с чужим Origin и получит 403.

    Цена. Запросы без Origin и Referer проходят (curl, старые браузеры, прокси, срезавшие заголовок) токен от этого не защитил бы тоже, но формально дыра уже не закрыта полностью. Обратный прокси обязан пробрасывать Host честно. Это зафиксированное послабление, а не недосмотр.

    SPA на vanilla JS без сборки¶

    Контекст. Интерфейс: форма, список замечаний, пара таблиц, админки. Разработчиков-фронтендеров в проекте нет, деплоить хочется копированием файлов.

    Решение. Семнадцать ES-модулей, hash-роутер на 44 строках, полный перерисов экрана, никакого фреймворка, бандлера и package.json. Nginx просто раздаёт каталог.

    Почему не фреймворк. React со сборкой добавили бы в проект toolchain, lock-файлы и слой абстракции, который здесь окупается только на экране SSE-стрима (и тот написан на rAF и TextNode напрямую). 4300 строк ванильного JS это потолок, после которого начался бы рост багов от самодельных абстракций; сейчас он близко, и это главный риск решения.

    Цена. Нет типобезопасности, переиспользование только через функции, состояние в голом объекте state, кэш-бустинг ?v= руками. Известные микроскопические дефекты (неимпортированные переменные в двух error-ветках) прямое следствие отсутствия сборки и линтера по JS.

    Проверка в два класса: движки плюс модель, поверх верификатор¶

    Контекст. Только детерминированные правила не ловят канцелярит, смысл и следование гайду формулировками. Только модель галлюцинирует замечания и невоспроизводима.

    Решение. Детерминированный слой (LanguageTool, Vale, pymorphy3) даёт воспроизводимые находки; LLM-воркеры дают смысловые; мост evidence.py приводит движки к схеме кандидата модели; верификатор (воркер 6) режет кандидатов, которые не выдерживают сверки с текстом и правилом. Правила с machine_verifiable: true идут в обход верификатора: они не врут по построению. Финальная страховка детерминированные дропы в schemas.py: span_text обязан быть подстрокой блока, правка не совпадать с оригиналом, constraints правила не нарушаться самой правкой.

    Цена. Лишняя стадия это лишние вызовы модели и задержка. Модель может зарезать честную находку (recall верификатора измеряется eval'ом, порог 0.80). Итог не на 100% воспроизводим: при temperature 0 он воспроизводим практически, но гарантии API провайдера никто не даёт.

    Репозиторий правил в трёх копиях¶

    Контекст. Vale читает свои YAML, модели нужен человекочитаемый текст правила, Python-коду нужны метаданные (движок, приоритет, связи, ограничения).

    Решение. style_guide_registry.py (56 записей) источник метаданных, styleguide/rules.yaml генерируется из него (_generate.py) и кормит LLM/RAG, vale/styles/RuStyleGuide/*.yml (48 файлов) исполняемые детекторы. Расхождение карается test_styleguide_consistency.py.

    Почему не один формат. Единый DSL пришлось бы писать самим, и он умер бы на половине: Vale не принимает чужой формат, модель не читает regex. Три копии со скрепляющим тестом дешевле собственного парсера.

    Цена. Любое правило это три файла и регрессионный кейс. Порог входа для мелкой правки текста правила выше, чем хотелось бы (для админов есть обход через UI-гайды, но он не создаёт новые Vale-детекторы).

    SQLite и JSON-файлы вместо Postgres¶

    Контекст. Данных мало: пользователи, гайды, история 50 записей на человека, очереди джобов на час, снимки страниц. Бэкап должен быть одной командой и одним файлом.

    Решение. SQLite для таблиц с конкурентной записью (jobs.db, stats.db, watch.db, extract_jobs.db), JSON для редких конфигурационных деревьев (users.json, гайды, папки репозитория), blob-файлы для версий документов. Весь штат под /app/data том, бэкап tar.gz каталога с ротацией 7 снимков.

    Цена. Один писатель на файл (threading.Lock) вместо транзакций; история урезана до 50 записей, задачи живут час после завершения; никакого запроса «сделай джойн через год». Для масштаба команды это потолок, но потолок далёкий и честно описанный.

    Прокси-страница мониторинга: httpx и всегда chromium¶

    Контекст. Мониторинг сравнивает живые страницы портала. Статический fetch врёт: SPA-контент подгружается скриптами, и сравнение html без рендера показывало бы бесконечный шум.

    Решение. Сначала httpx (с form/basic логином), затем если chromium поднят, перерендер playwright'ом и уже DOM-копия участвует в диффе. Копия отдаётся пользователю самодостаточным HTML с вырезанными скриптами, замороженными кликами, base-URL на оригинал и инлайновыми шрифтами под бюджет 2 МиБ.

    Цена. Chromium в образе backend (несколько сотен МБ, плюс память на процесс браузера), опрос страниц дольше, съём зависит от доступности внешнего рендера (503 без него). Хранение копий чужих страниц юридически зона ответственности оператора; технически снимок приватен: PII маскируется (телефоны, почты, карты, СНИЛС, ИНН) до записи в базу.

    Редиректы шагаются руками (SSRF)¶

    Контекст. Сервис ходит по URL от пользователей. Автономные редиректы HTTP-клиента обходят любую DNS-проверку: публичный адрес редиректит на 169.254.169.254.

    Решение. follow_redirects=False, каждый hop ре-резолвится и ре-проверяется, POST на редиректе понижается до GET (учётные данные формы не улетят на чужой хост). Приватные сети по умолчанию разрешены (PROOFREADER_SSRF_ALLOW_PRIVATE=true) сервис для интранет-документов, на публичном хосте флаг обязан быть false.

    Цена. TOCTOU между проверкой и подключением не закрыт (нет pinning'а IP) классическая атака DNS-rebinding с коротким TTL теоретически возможна; закрывается только своим transport-слоем, на который пока не пошли секунды. Ручные редиректы ещё и ломают edge-cases провайдеров, которые шлют тело с 302.

    Теневой режим конвейера¶

    Контекст. Переход v1→v2 нельзя было делать big bang: отчёт должен остаться приемлемым для пользователей в любой момент.

    Решение. PIPELINE_VERSION переключает основной конвейер, PIPELINE_SHADOW гоняет оба и пишет сравнение ключей (block_index, rule_id, replacement) в meta.shadow_comparison. Кэш клиента модели включает версию пайплайна, промптов и RAG-конфига в namespace, поэтому эксперимент не травит продакшн-кэш.

    Цена. Двойной расход токенов на время сравнения; поддержка двух пайплайнов в одном дереве (pipeline.py + pipeline_v2.py ~1170 строк). После стабилизации v1 остаётся «для откатов», это постоянный налог на чтение кода.

    SSE плюс страховочный поллинг¶

    Контекст. Прогресс длинной задачи надо показывать живьём, но корпоративные прокси и старые браузеры режут стримы молча.

    Решение. Фронт открывает EventSource и одновременно опрашивает GET /api/jobs/{id} раз в 1.2 секунды; при потере стрима тост и переход на один поллинг. Сервер стримит токены модельных ответов блоками с капом 20 000 символов и подрезкой начала.

    Цена. Лишние 50 запросов в минуту на клиента; порядок «правда в двух каналах» требует аккуратности в финализации (защита от двойного finishJob). Взамен никто не зависает на пустом экране.

    Что сознательно не делается¶

    • PKCE в OIDC state+nonce есть, code challenge нет: redirect URI статичен и настраивается админом, угроза перехвата кода на публичном клиенте не наш сценарий (конфиденциальный клиент с секретом).
    • Принятие замечаний в интерфейсе у LLM-находок нет персистентного accept/reject: скрыл/показал локально, сервер не знает. Упорядоченного review-flow с назначением правок нет, потому что итоговая выгрузка xlsx и так закрывает рабочий цикл команд.
    • Мультиязычность UI частичная: словарь i18n/ на 44 ключа, всё остальное зашито по-русски. Продукт для русской вычитки, второй язык не запрашивали.
    • Публичные API-ключи (как у SaaS) аутентификация только сессионная; для интеграций ожидается login+cookie. Сознательно: сервис внутренний.
    • Swagger по умолчанию выключен (PROOFREADER_DOCS=false) не секрет-полиция, а снижение поверхности: schema доступна после входа, но лишний хелпер атакующему не подарим.
