    Быстрый старт: первая проверка за пять минут¶

    Эта страница проводит через первый запуск: поднять сервис, зайти, подключить модель, проверить текст. Предположим, что Docker уже установлен; если нет, сначала Установка и запуск.

    Что понадобится¶

    • Docker Engine с docker compose v2 (или docker-compose).
    • Свободный порт 3080 на хосте (или другой, если настроите).
    • Примерно 3.5 ГБ памяти: 1.5 ГБ на LanguageTool, до 2 ГБ на приложение.
    • Ключ и адрес совместимой с OpenAI модели, если хотите полноценную проверку гайдом. Без модели сервис тоже работает, но только формальными движками.

    Поднять сервис¶

    git clone https://github.com/BadWisher/Peter-View
cd Peter-View
./deploy.sh

    Скрипт скопирует .env.example в .env, соберёт образы и поднимет три контейнера: backend, фронтенд на nginx и LanguageTool. Первый запуск занимает около полуторы минуты, LanguageTool на Java стартует дольше всех.

    Когда стек поднимется, скрипт напечатает доступные адреса. Откройте http://localhost:3080.

    Зайти под админом¶

    Первый вход: логин admin, пароль admin. Сервис создаёт эту учётку автоматически, когда база пользователей пуста. Сразу заведите себе нормальный пароль: меню аккаунта вверху справа, «Сменить пароль», минимум 8 символов. Лишних людей добавляйте в разделе «Пользователи» и тоже заставляйте менять пароль.

    Подключить модель¶

    Без модели доступны только LanguageTool, Vale и морфологические проверки. Чтобы включить разбор по стилевым гайдам и поиск смысловых противоречий, админ заполняет раздел «Настройки»:

    Поле Что вписать
    Базовый URL (LLM_BASE_URL) адрес API, совместимого с OpenAI, например https://api.openai.com/v1
    Модель (LLM_MODEL) имя модели, например gpt-4.1-mini
    Ключ (LLM_API_KEY) секретный ключ провайдера
    URL эмбеддингов, модель эмбеддингов опционально, нужны для поиска по длинным гайдам

    Ключ вводится один раз и больше не показывается: поле остаётся пустым, а сервис хранит значение. Кнопка «Проверить подключение» дёргает оба адреса и честно говорит, что не так. Если модель доступна только через корпоративный прокси, включите PROOFREADER_CORP_PROXY=true в .env и перезапустите deploy.sh.

    Проверить первый текст¶

    1. Раздел «Вычитка», вкладка «Текст».
    2. Вставьте фрагмент документации или статьи.
    3. Отметьте группы проверок: «Язык и ясность», «Style Guide», «Термины и согласованность». хотя бы одна обязательна.
    4. Нажмите «Проверить».

    Сначала идёт быстрая часть: формальные движки. Затем модель читает текст частями, и прогресс виден по карточкам воркеров в реальном времени. Готовый отчёт открывается на странице разбора: слева текст с подсветкой, справа список замечаний. Как с ним работать, описано в Разборе замечаний.

    Для контроля возьмите заведомо плохой фрагмент, например:

    Данный модуль позволяет осуществлять синхронизацию данных между системами.
Он был разработан нами в прошлом году, и мы можем гарантировать его надежность.

    Хороший ответ содержит замечания на «данный», канцелярит «позволяет осуществлять», пассив и anthropomorphism «мы можем гарантировать». Если формат вывода незнаком, почитайте Как устроена проверка, там объясняется, почему ответы такие, а не другие.

    Если что-то не работает¶

    Быстрая диагностика по симптомам на странице Неполадки. Частые причины: не заполнены настройки модели (проверка падает на LLM-воркерах), LanguageTool ещё не поднялся (первая проверка висит), порт 3080 занят другим приложением.
