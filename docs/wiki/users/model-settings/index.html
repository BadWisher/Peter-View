    Языковая модель¶

    Эта страница описывает раздел Настройки с точки зрения пользователя интерфейса: какие поля там есть, что они значат, как сервис их применяет и что видят остальные сотрудники, когда модель не настроена. Страница нужна администратору, который подключает модель и эмбеддинги, и редактору, который хочет понять, почему отчеты по гайдам пустые.

    Страница отвечает на вопросы: какие значения ввести, почему API-ключ показывается один раз, когда настройки применяются без рестарта и сколько стоит проверка. Те же параметры через переменные окружения описаны в Implementation Guide на странице Переменные окружения, а механика клиента модели относится к разделу Архитектура.

    Доступность раздела¶

    Раздел Настройки доступен только администраторам. Обычные пользователи его не видят, но замечают отсутствие модели по поведению проверок: воркеры модели помечаются ошибкой или пропуском, а в отчете появляется плашка о частичной проверке. Если команда жалуется на пустые отчеты по гайдам, первым делом стоит проверить настройки модели.

    Поля раздела Модель¶

    Раздел Модель настраивает основной внешний сервис проверки. Вид заполненной формы показан ниже.

    Назначение полей приведено в таблице ниже.

    Поле Смысл Примечание
    Адрес API OpenAI-совместимая конечная точка, например https://api.openai.com/v1 обязателен для модельных проверок; без него они выключены
    Модель имя модели у провайдера свободная строка, знает ли провайдер такое имя, решает он
    API-ключ секрет вводится один раз: поле показывает Ключ задан, значение не отдается наружу и не затирается пустой отправкой
    Температура от 0 до 2 с шагом 0.1, по умолчанию 0 для вычитки держите 0, чтобы правки были воспроизводимы
    Параллельность от 1 до 20, по умолчанию 3 в интерфейсе сколько запросов к модели сервис отправляет одновременно

    Поля раздела Эмбеддинги¶

    Раздел Эмбеддинги содержит адрес API, модель и ключ. Эмбеддинги нужны для гибридного подбора правил из длинных гайдов. Короткий гайд, примерно до 30 правил, модель получает целиком. Из длинного гайда под каждый фрагмент текста отбираются релевантные правила, и для этого используется поиск по эмбеддингам.

    Без настроенных эмбеддингов подбор деградирует до лексического, по ключевым словам. Такой режим хуже работает на объемных сводах правил, потому что может пропустить норму, сформулированную иными словами.

    Поля раздела Выполнение¶

    Раздел Выполнение управляет тем, как сервис ждет ответы модели. Назначение полей приведено в таблице ниже.

    Поле Смысл
    Тайм-аут, секунд от 5 до 600, по умолчанию 120; сколько ждем один ответ модели
    Усилие рассуждения Низкое, Среднее или Высокое; параметр рассуждающих моделей, который провайдер игнорирует для обычных chat-моделей
    JSON-режим просить у модели структурированный JSON-ответ; с ним разборов с ошибкой формата меньше, но поддерживают его не все провайдеры

    Проверка подключения¶

    Кнопка Проверить подключение обращается к модели и к эмбеддингам короткими запросами, с ожиданием до 30 секунд на каждый сервис, и показывает результат по именам: отдельно строку для модели и отдельно для эмбеддингов.

    Ответ приходит с кодом 200 даже при неудаче, а текст ошибки находится в теле ответа. Это первый инструмент диагностики: если проверки валятся на модельных воркерах, начинать стоит с этой кнопки, а не с чтения логов.

    Поведение при сохранении¶

    Ниже перечислены правила, которые важно знать при редактировании настроек.

    • Пустые поля не отправляются, и сохраненные значения остаются. Очистить адрес API или имя модели через интерфейс нельзя, можно только вписать новое. Так сделано намеренно для секретов.
    • Настройки применяются на лету: клиенты модели пересоздаются по подписке на изменения, рестарт сервера не нужен.
    • Файл data/llm_settings.json записывается с правами 0600. Резервная копия каталога data/ уносит и ключи, поэтому архивы нужно хранить соответственно.

    Стоимость и расход¶

    Каждая проверка с моделью расходует токены. Документ режется на фрагменты по 8 блоков с перекрытием в 2 блока; для больших документов размер фрагмента растет, но их число не превышает 24. Каждый фрагмент проходит нужные воркеры, а сверху результаты проверяет верификатор. Полный расчет по типовому документу на 50 тысяч знаков дает десятки обращений к модели.

    Счет токенов виден в разделах Аналитика и Система. Если тариф провайдера небольшой, снизьте параллельность и рассчитывайте на кэш запросов. Кэш включен всегда: одинаковые сочетания фрагмента и промпта не уходят в модель повторно в течение жизни процесса.
