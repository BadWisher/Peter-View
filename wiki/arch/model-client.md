# Клиент модели и эмбеддингов

`backend/app/llm/client.py` одна точка выхода в языковую модель. `backend/app/llm/rag.py` клиент эмбеддингов для подбора правил. Оба работают через OpenAI-совместимые HTTP-API, адреса и ключи задаёт админ ([настройки](../users/model-settings.md), [переменные](../ops/config-env.md)).

## Модель

Транспорт пакет `openai`, `AsyncOpenAI` с `base_url = llm_base_url`, `api_key = llm_api_key`. Любой провайдер с OpenAI-совместимым `/chat/completions` подходит.

### Вызов

`complete_json(system, user, on_delta=None)` основной метод, которым пользуются все воркеры:

- ответ разбирается как JSON (`_extract_json` вытаскивает объект из текста, терпит markdown-обёртки);
- при `llm_json_mode` добавляется `response_format={"type":"json_object"}`; если провайдер отклоняет json_mode или reasoning-параметр, идёт деградация попыток: сначала как есть, потом без json, потом без reasoning;
- при непустом `llm_reasoning_effort` (low/medium/high) параметр передаётся, у моделей без reasoning провайдер его игнорирует или отклоняет, и вызов повторяется без него.

### Стриминг

Если передан `on_delta`, запрос идёт `stream=True`, и в колбэк летят токены «живой речи» (рассуждения) воркера, не финальный JSON. Так у пользователя в карточке воркера печатается текст в реальном времени. Если провайдер не умеет стриминг (`BadRequestError`), деградация до обычного `create`.

### Параллельность, ретраи, кэш

- `_semaphore = Semaphore(llm_concurrency)` ограничивает одновременные обращения к модели (создаётся заново при смене настроек через listener).
- `MAX_RETRIES` попыток; паузы: `RateLimitError`/`APITimeoutError` `min(30, 3·2ⁿ)`; ошибки, которые пахнут лимитом токенов (в т.ч. HTTP 402) `min(45, 5·2ⁿ)`; временные `APIError` `min(30, 3·2ⁿ)`; битый JSON пауза 1 с и повтор. Прочие ошибки фатальны, бросается `LLMRequestError` с обезличенным сообщением.
- Кэш двухуровневый по хэгу `(system, user, temperature)`: in-process `_cache` (FIFO на `CACHE_MAX=1024`) и персистентный (`stats.cache_set`, живёт в базе). Перезапуск не обнуляет кэш: одинаковый промпт не гоняется в модель повторно. Это и экономия токенов, и источник артефакта: если поменялась только версия промпта, хэш другой, кэш сам инвалидируется.

### Учёт токенов

`stats.record_tokens(prompt, completion, cached)` на каждый ответ (у части провайдеров `cached_tokens` лежит в `prompt_tokens_details`). Агрегаты идут в «Аналитику» и «Систему», пометка воркера через `usage_stats.set_worker` (кто сколько сжёг).

### Healthcheck

`healthcheck()` короткий `create` без JSON-режима (`max_tokens=16`, потому что reasoning-модели тратят бюджет на рассуждение), таймаут 20 с в `/api/health/full` и 30 с в `/api/settings/test`. Пустой `llm_base_url` явная ошибка «LLM не настроен».

## Эмбеддинги и RAG

`rag.py` подбор правил гайда под конкретный фрагмент текста. Нужен, когда гайд большой и все правила в промпт не влезают.

- Отдельный OpenAI-совместимый endpoint (`embedding_base_url/_api_key/_model`), пакет `openai`, синхронный `OpenAI`. `EMBED_BATCH_SIZE` (90) за раз, `EMBED_TIMEOUT` (20 с).
- Индекс в памяти по каждому гайду (ключ id гайда), перестройка по `content_hash`. Правила превращаются в «документы» (title + формулировка + generalize + примеры), косинусная близость на numpy (правил десятки, внешнее векторное хранилище не нужно).
- `ensure_index(guide)` вызывается в начале конвейера, прогревает индекс; `healthcheck()` есть отдельный, светится в `/api/health/full` строкой «Эмбеддинги».
- `retrieve(query, guide, task, k)`: семантические скоры (`_semantic_scores`) складываются с лексическими (`_lexical_scores`, по токенам) и бустом по метаданным (`_metadata_boost`: категория, область применения правила). Гибрид это то, что UI показывает как «гибридный» индекс в статусе гайда.
- Деградация без эмбеддингов: если endpoint недоступен, `retrieve` отдаёт все правила гайда (лексический/полный режим, «lexical_only» в `index-status`). На маленьких гайдах это безвредно, на больших хуже точность подбора, но работает.

`RAG_CONFIG_VERSION` (env) версионзирует схему кэша индексов, чтобы смена формата не подмешивала устаревшие векторы.

### Что делает RAG для конвейера

Пайплайн v2 вызывает `_retrieve_batch` для чанков и `_retrieve_one` для терминологии/согласованности. Подобранные правила (top-k) подставляются в промпт воркера, поэтому модель проверяет не «вообще всё», а релевантные этому фрагменту нормы. Диагностика подбора (`meta.retrieval.rule_hit_counts`, `rules_never_offered`) показывает, какие правила не предложил ни один запрос плохой признак: правило сформулировано так, что эмбеддинг его не находит, и проверка его фактически не делает.
