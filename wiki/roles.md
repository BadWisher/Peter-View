# Роли и доступ

Две роли: `admin` и `editor`. Сид при первом старте: пользователь `admin`, пароль `admin`, роль администратора. Пароль не короче 8 символов.

Новый локальный пользователь всегда создаётся редактором. Администратор потом может повысить.

| | Администратор | Редактор |
|---|---|---|
| Вычитка, история, аналитика | да | да |
| Документы, API, наблюдение, скриншоты | если раздел включён флагом | то же |
| Style Guide: чтение и выбор для проверки | да | да |
| Style Guide: создание, правка, удаление | да | 403 |
| Свои пароль и тема | да | да, пароль только у локальных |
| Пользователи и роли | да | нет |
| Настройки модели | да | нет |
| Экран «Система» | да | нет |

Последнего администратора нельзя удалить и нельзя понизить. Себя удалить нельзя.

Сессия живёт 12 часов, cookie `proofreader_session`, HttpOnly, SameSite=lax. Secure включается `PROOFREADER_COOKIE_SECURE`.

## OIDC

Если заданы `OIDC_ISSUER` и `OIDC_CLIENT_ID`, на экране входа появляется кнопка «Войти через организацию».

Поток: authorization code. Discovery: `OIDC_ISSUER/.well-known/openid-configuration`. Scope: `openid profile email`.

Человек из IdP попадает в сервис без пароля. Роль `editor`, пока одна из групп в токене не совпадёт с `OIDC_ADMIN_GROUPS`.
