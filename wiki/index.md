# Документация Peter View

Peter View это веб-сервис проверки русскоязычных текстов: документации,
статей, описаний продуктов, страниц сайтов. Он находит опечатки, ошибки
согласования, канцелярит, длинные предложения, расхождения с корпоративным
Стайл гайдом и внутренние противоречия термина. Проверка не заменяет
редактора: она выдает размеченные замечания с предлагаемыми правками, а
решение по каждому замечанию принимает человек. Результат можно посмотреть в
браузере и выгрузить в XLSX для передачи автору текста.

## Назначение сервиса

Сервис принимает три вида входа: текст из буфера обмена, загружаемый файл и
адрес веб-страницы. Файл поддерживается в форматах DOCX, TXT, HTML и MD,
структура документа (заголовки, списки, таблицы) сохраняется в отчете.
Кроме разовой проверки доступны три постоянных сценария: хранение версий
документов с историей правок, наблюдение за живыми страницами сайта с
ежедневным обходом и сравнение пар русскоязычной и англоязычной
OpenAPI-спецификаций.

Границы применимости важно понимать до начала работы. Сервис не выполняет
перевод текстов и не генерирует контент. Он не проверяет фактическую
точность утверждений сверх того, что записано в подключенных Стайл гайдах
и словарях терминов: вымышленное утверждение о свойствах продукта будет
замечено только в том случае, если соответствующая норма явно внесена в гайд.
Ошибки в тексте на картинках сервис не видит, если этот текст не загружен
отдельным файлом.

## Устройство проверки текста

Каждый текст проходит два класса проверок. Первый класс это
детерминированные движки: LanguageTool для грамматики и пунктуации, Vale для
паттернов оформления прозы, морфологические проверки на библиотеке pymorphy3. Их
находки воспроизводимы и не зависят от внешних сервисов. Второй класс это
языковая модель: она сверяет текст со Стайл гайдом команды, ищет смысловые
противоречия и расхождения терминов. Находки модели не попадают в отчет
напрямую. Каждая из них проходит верификатор, который отклоняет замечания без
ссылки на конкретное правило и без реального вхождения спорного фрагмента в
текст. Подробное описание стадий, параллельности и ограничений находится в
разделе [**Архитектура**](arch/overview.md), начать стоит со страницы [**Общая архитектура**](arch/overview.md).

## Структура документации

Документация делится на четыре раздела по аудитории. Каждый раздел
самодостаточен внутри своей роли, а перекрестные ссылки ведут в соседние
разделы, когда это нужно читателю.

- [**User Guide**](users/quickstart.md) предназначен для редакторов, авторов текстов и технических
  писателей. В нем описана работа с интерфейсом: проверка текста, разбор
  замечаний, Стайл гайды, история, документы, наблюдение за страницами.
  Код в этом разделе не требуется, и предполагается, что сервис уже
  развернут администратором.
- [**Архитектура**](arch/overview.md) описывает устройство сервиса и принятые проектные решения.
  Она нужна тем, кто читает код, оценивает безопасность или спорит с
  выбранной схемой: конвейер проверки, движки, клиент модели, модель данных,
  механизмы защиты.
- [**Developer Guide**](dev/setup.md) проводит по коду репозитория: рабочее окружение, карта
  модулей, конвенции бэкенда и фронтенда, HTTP API, тестирование, поддержка
  самой документации.
- [**Implementation Guide**](ops/deploy.md) содержит все операции развертывания и
  эксплуатации на сервере: деплой, стек контейнеров, переменные окружения,
  TLS, резервные копии, обновления, наблюдение, жесткая настройка, вход
  через OIDC, дежурство по инцидентам.

## Быстрый вход в материал

Для разных задач стартовые страницы различаются. Список ниже приводит
рекомендуемую последовательность чтения по типу читателя.

- Редактору, который получил адрес и учетную запись: [Первые шаги](users/quickstart.md),
  затем [Проверка текста, файла и веб-страницы](users/check.md) и
  [Разбор замечаний](users/review.md).
- Администратору, который поднимает сервис: [Развертывание](ops/deploy.md),
  затем [Переменные окружения](ops/config-env.md).
- Разработчику, который правит код: [Рабочее окружение](dev/setup.md), затем
  [Карта кода](dev/code-map.md).
- Читателю, который хочет понять, почему отчет выглядит именно так:
  [Общая архитектура](arch/overview.md).

## Версии и обратная связь

Актуальная версия ветки **main**. Полный список изменений по релизам ведется
в файле [CHANGELOG](https://github.com/BadWisher/Peter-View/blob/main/CHANGELOG.md)
репозитория. Сообщения об уязвимостях принимаются по процессу, описанному в
файле **SECURITY.md** того же репозитория; публичные issues для этого не
заводятся.
