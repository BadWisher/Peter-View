# Обновление версии

Обновление это либо пересборка из git, либо перетягивание образов из registry. Оба пути держат том `backend-data` на месте: данные не деваются. Миграций схемы нет код приложения сам читает старые форматы JSON/SQLite.

## Перед обновлением

1. Ручной снапшот: `make backup` (не забудьте потом почистить `manual-*`, автоматика их не трогает).
2. Проверить, что автоснапшот свежий: раздел «Система» строка «Резервная копия», либо `ls ./backups`.
3. Залогиньтесь заранее: обновление перезапустит backend, всех разлогинит.
4. Предупредите пользователей, что проверки на середине прервутся. Прерванные задачи после рестарта помечаются ошибкой «Прервано рестартом сервера» и не восстанавливаются.

## Из исходников (dev-путь)

```bash
make update
```

За `git pull --ff-only` и `./deploy.sh` следует пересборка изменённых слоёв и перезапуск контейнеров. Если pull не ff (локальные правки, разлетелись с upstream), pull откажет, и это правильно: разбирайтесь руками, не через `reset --hard`.

## Из образов (prod-путь)

```bash
export GHCR_REPOSITORY=<владелец/имя>
export IMAGE_SHA=<новый commit sha>
make prod-config   # валидность связки compose
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

Compose пересоздаст backend и frontend из новых образов, languagetool (pin по digest в базовом файле) не тронет. `pull_policy: always` гарантирует, что тег `:main` или sha реально перетянутся.

## Проверка после

```bash
docker compose ps                    # все healthy
make regression                      # самотесты внутри backend
curl -s localhost:3080/api/health    # {"status":"ok",...}
```

Прогоните одну короткую контрольную проверку (вкладка «Текст»), дождитесь LLM-воркеров если модель подключена. Это ловит типичные регресcии обновления: LanguageTool не поднялся, ключ модели слетел, формат ответа не парсится.

## Откат

Данные обратно tar-архивом (см. [Бэкап](backup.md)); образы переключением `IMAGE_SHA` на предыдущий коммит (`git log --oneline` перед обновлением спасает). Откат фронтенда без отката backend иногда приводит к несовместимости контрактов: новые фронты умеют в ответы старых бэкендов, наоборот нет.

## Что при обновлении может сломаться

| Симптом | Вероятная причина |
|---|---|
| `deploy.sh` пишет «не ответил за 60 с» при живом стеке | LT долго стартует на холодную; подождите, `make logs` покажет |
| Проверки падают на LLM-воркерах | настройки модели живут в томе и обычно переживают обновление, но если вы пересоздавали volume с нуля, ключи и модель пропали |
| Swagger `/api/docs` не открывается | жёсткий `PROOFREADER_DOCS=false` в compose (см. [переменные](config-env.md)) |
| 403 «Перекрёстный запрос отклонён» после смены адреса | вы поменяли хост/порт, браузер шлёт старый Origin; обновите закладки, проверьте `Host` на внешнем прокси |
