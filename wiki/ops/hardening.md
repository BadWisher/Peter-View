# Усиление защиты

Сервис запускается с разумными дефолтами для локального/интранет-использования. Для публичного хоста этого мало. Ниже чек-лист с обоснованием каждого пункта.

## Обязательный минимум (публичный хост)

| # | Действие | Зачем |
|---|---|---|
| 1 | Сменить пароль `admin/admin` | дефолт известен всем; до смены любой гость с доступом к порту становится админом |
| 2 | TLS через внешний прокси + `PROOFREADER_COOKIE_SECURE=true` | сессия не светится в сети |
| 3 | `PROOFREADER_SSRF_ALLOW_PRIVATE=false` | на публичном хосте пользователи не должны тыкать сервисом в внутренние адреса cloud-метаданных и localhost (защита от-metadata уже вшита, приватные сети по умолчанию разрешены) |
| 4 | Задать явный `PROOFREADER_SECRET` (или сохранить сгенерированный `data/watch.db.key` в бэкапах) | ключ обфускации паролей и снимков в watch-хранилище; без явного значения сервис генерирует ключ сам при первом запуске |
| 5 | `PROOFREADER_DOCS` остаётся false | Swagger наружу не нужен, а отключить его через `.env` нельзя (переопределён в compose, см. [переменные](config-env.md)) |
| 6 | Не включать `FEATURE_WATCH`/`FEATURE_API` без нужды | каждый флаг это дополнительный путь обращения наружу по пользовательским адресам |
| 7 | Бэкапы в зашифрованное хранилище | в тар-архиве лежат API-ключи и bcrypt-хэши паролей |

## Модель угроз, о которой стоит помнить

**Кто вообще попадает в сервис.** Логин-пароль или OIDC, rate limit 5 попыток/5 минут на пару IP+логин. Пароли минимум 8 символов без требований сложности это реально слабое место публичного инстанса: включайте OIDC или закрывайте вход IP-политикой прокси.

**Что делает аутентифицированный редактор.** Загружает файлы и URL в проверку (текст уходит в настроенную админом LLM), читает/экспортирует отчёты, управляет общим репозиторием документов без прав доступа по папкам. Роли editor доверенные люди, не случайные гости.

**SSRF.** Все пользовательские URL (проверка по ссылке, Мониторинг) проходят `net_guard`: схема http/https, резолвинг DNS с блокировкой loopback/link-local (включая 169.254.169.254)/multicast/reserved, перепроверка на каждом редиректе (до 5), лимит тела 10 МБ. Приватные сети по умолчанию разрешены. **Не проходят guard**: адреса OIDC-провайдера и LLM/эмбеддингов (их задаёт админ, доверенный вход), LanguageTool.

**XSS в отображении находок.** Весь пользовательский текст экранируется, подсветка строится событийным потоком открытых/закрытых меток. Отдельная защита у сохранённых копий страниц: `<iframe sandbox>` + CSP `script-src 'none'`.

**Сессии.** Cookie `proofreader_session`, HttpOnly, SameSite=Lax, 12 часов скользящие. CSRF-защита сверкой Origin/Referer с Host (не токен; на нестандартных прокси с переписанным Host возможны ложные 403). Нет global 401-редиректа: протухшая сессия показывается ошибкой в UI.

## Что не закрыто в самой сборке (решать снаружи)

| Дыра | Митигация на площадке |
|---|---|
| Нет rate limit на nginx по IP (брутфорс API после входа не лимитирован) | limit_req на внешнем прокси |
| Нет HSTS | add_header Strict-Transport-Security на внешнем TLS-прокси |
| Vale-бинарь в Dockerfile без фактической проверки sha256 (комментарий обещает, кода нет) | пиньте итоговый образ по digest после ревью; не собирайте из непроверенных форков |
| Base-образы пинятся по digest, но Dependabot следит только за pip | отдельно обновляйте digest'ы образов, иначе они тихо устаревают |
| Логи 30 МБ на сервис без внешней агрегации | сбор логов, если нужен forensic-след дольше этого |
| corp-proxy мост `172.17.0.1:3128` без аутентификации | firewall: запретить вход на 3128 извне bridge-сети; поднимать только на VDI |

## Секреты: где лежат и кто читает

| Секрет | Место | Права |
|---|---|---|
| Пароли (bcrypt) | `data/users.json` | том backend-data; файл world-readable внутри контейнера (0644 по umask) |
| API-ключи модели/эмбеддингов | `data/llm_settings.json` | 0600, маскируются в API (наружу уходит пустая строка + флаг «ключ задан») |
| Пароли групп Мониторинга | `data/watch.db` | обфускация ключом из `PROOFREADER_SECRET` (или сгенерированным и сохранённым в `data/watch.db.key`); это XOR-обфускация, а не криптозащита |
| `OIDC_CLIENT_SECRET`, `LLM_API_KEY` в `.env` | каталог репозитория на хосте | держите `chmod 600 .env`, не коммитьте `.env` |
