# История проверок и аналитика

Каждая завершённая проверка записывается в историю: источник, дата, выбранный гайд, число находок по уровням. Отчёт хранится целиком и открывается в любой момент.

## Список историй

Раздел «История». Таблица: «Источник», «Дата», счётчики ошибок, замечаний, советов, «Гайд». Клик по строке открывает сохранённый отчёт в обычном режиме [разбора](review.md): та же подсветка, те же фильтры и экспорт.

Хранится по 50 последних записей на пользователя, старые вытесняются. Записи видны только их автору: история это личный журнал. Раздел «Аналитика» ниже показывает статистику по всем сотрудникам, но только по числу срабатываний, без текстов документов.

## Отменённые и прерванные задачи

Нажатие «Вернуться» во время проверки не отменяет саму задачу: она досчитается и попадёт в историю. Если backend перезапустился на середине работы, задача помечается прерванной, недоделанный отчёт не сохраняется. Запустить её заново можно только новой проверкой.

## Аналитика

Раздел «Аналитика» отвечает на вопрос «что чаще всего ломает наша команда?»:

- полоса счётчиков: токенов всего и сегодня, всего срабатываний правил, число авторов проверок;
- топ-правил по каждому пользователю: полоски с долей срабатываний, рядом описание правила и число попаданий.

Аналитика считается по всем пользователям, доступ к разделу есть у всех, но данные персональные (ник + правила). Если правило стабильно в топе у половины команды, значит текст учат не по гайду, а по памяти: либо повышайте строгость правила, либо пишите его так, чтобы оно стало очевидным.

## Программный доступ

История и аналитика доступны через HTTP API: `/api/checks/history`, `/api/checks/history/{id}`, `/api/checks/insights`. Формат ответов описан в [HTTP API](../dev/api.md).
