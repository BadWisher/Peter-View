# Спецификации API

Эта страница описывает раздел [**Спецификации API**](openapi.md), который включается флагом
`FEATURE_API`. Раздел нужен командам, которые ведут публичный API на двух
языках: русская и английская версии одной OpenAPI-спецификации должны
совпадать по структуре и не противоречить друг другу. Сервис сопоставляет их
поле за полем, находит расхождения, проверяет формулировки моделью и
предлагает перевод измененных фрагментов.

Страница отвечает на вопросы: как подготовить связку, чем отличаются три
вкладки работы и что умеют два режима модельного разбора. Как включить флаг
раздела, описано на странице [**Дополнительные разделы интерфейса**](sections.md).

## Подготовка связки

Для работы раздела нужны два файла спецификации. Порядок подготовки приведен в
шагах ниже.

1. Загрузите русскую и английскую версии спецификации в раздел [**Документы**](documents.md).
   Флаг `FEATURE_DOCUMENTS` при этом тоже должен быть включен, потому что
   связка ссылается на документы из хранилища.
2. На вкладке **Связки** создайте пару: название, документ RU, документ EN.
   Одна связка соответствует одной спецификации в двух языках.

## Вкладки работы

Раздел содержит три вкладки, каждая из которых отвечает на свой вопрос. Их
назначение описано ниже.

**Поля.** Спецификация разбивается на сегменты, где сегмент это описание
одного пути или одной схемы. Список сегментов показывается страницами по 50
элементов с поиском и задержкой ввода 300 мс. Каждый сегмент показывает
русскую и английскую версии рядом. Текст можно отредактировать прямо в полях,
правки копятся локально и применяются кнопкой выгрузки измененной YAML; сервер
отдает файл с именем вида `<имя>_edited.yaml`. Клик по пути копирует его в
буфер обмена.

**Единообразие.** Вкладка отвечает на вопрос, одинаково ли названы сущности по
всей спецификации. Сервис собирает статистику по терминам и показывает, где
RU и EN разошлись; типовой пример: термин «пользователь» местами переведен как
**client**. Кнопка вида **N в полях** уводит в конкретный сегмент с расхождением.

**Изменения.** Вкладка сравнивает текущую и предыдущую версию загруженного
документа. Результат это список измененных путей с русским и английским
текстом рядом.

## Режимы модельного разбора

На связке доступны две кнопки: **ИИ-проверка** и **Перевести**. Обе ставят
фоновую задачу на тот же механизм очередей, что и вычитка; статус обновляется
опросом раз в секунду, выполнение занимает до 10 минут. Режимы различаются
следующим образом.

- **ИИ-проверка** прогоняет измененные сегменты через модель и возвращает
  список замечаний к формулировкам. Это та же работа, что и в вычитке, но
  точечно по диффу.
- **Перевод** берет измененный русский текст и предлагает английскую пару для
  каждого сегмента. Результат является черновиком перевода и не заменяет
  переводчика.

Если с момента последней версии изменений нет, задача вернет сообщение об их
отсутствии без замечаний.

## Ограничения раздела

Ниже перечислены свойства, о которых нужно знать при планировании работы.

- Раздел рассчитан на связку из одной RU и одной EN версии. Многоязычные
  матрицы из трех и более языков не поддерживаются.
- Изменения считаются относительно предыдущей загруженной версии документа, а
  не относительно эталонной. Порядок версий ведите сами: сервис хранит их, но
  не подсказывает, какую считать релизной.
- Выгрузка YAML с правками применяет только ваши ручные правки из вкладки **Поля**. Результаты модельного перевода нужно копировать вручную.
- Как и раздел [**Документы**](documents.md), доступ к связкам общий для всех редакторов.
