# Проверка OpenAPI-спецификаций (раздел «API»)

Включается флагом `FEATURE_API` ([как включить](sections.md)). Раздел нужен тем, кто ведёт публичный API на двух языках: русская и английская версии одной OpenAPI-спецификации должны совпадать по структуре и не противоречить друг другу. Сервис сопоставляет их поле за полем, ищет расхождения, проверяет формулировки моделью и переводит изменённые куски.

## Подготовка

1. Загрузите RU- и EN-версии спецификации в раздел «Документы» (флаг `FEATURE_DOCUMENTS` при этом тоже нужен: связка ссылается на документы из хранилища).
2. Во вкладке «Связки» создайте пару: название, документ RU, документ EN. Одна связка одна спецификация в двух языках.

## Три вкладки работы

**Поля.** Спецификация разбивается на сегменты (описание одного пути/схемы), страницы по 50 с поиском (задержка 300 мс). Каждый сегмент показывает русскую и английскую версию рядом; текст можно отредактировать прямо в полях, правки копятся локально и применяются кнопкой выгрузки изменённой YAML (сервер отдаёт `<имя>_edited.yaml`). Клик по пути копирует его в буфер.

**Единообразие.** Отвечает на вопрос «одинаково ли названы сущности по всей спеке»: сервис собирает статистику по терминам и показывает, где RU и EN разошлись (например, «пользователь» местами «клиент»). Кнопка «найти в полях» уводит в конкретный сегмент.

**Изменения.** Сравнение текущей и предыдущей версии загруженного документа: список изменённых путей с русским и английским текстом рядом.

## Два ИИ-режима

Кнопки «ИИ-проверка» и «Перевести» на связке ставят фоновую задачу (тот же механизм jobs, опрос раз в секунду, до 10 минут):

- **ИИ-проверка** прогоняет изменённые сегменты через модель и возвращает список замечаний к формулировкам (как в вычитке, но точечно по диффу).
- **Перевод** берёт изменённый русский текст и предлагает английскую пару для каждого сегмента. Это черновик перевода, не замена переводчику.

Если изменений нет, задача вернёт сообщение «Изменений для проверки нет» без замечаний.

## Ограничения

- Раздел рассчитан на связку «одна RU + одна EN». Многоязычные матрицы (три языка) не поддерживаются.
- Изменения считаются относительно предыдущей **загруженной версии документа**, а не относительно эталонной. Порядок версий ведите сами: сервис их хранит, но не подсказывает, какую считать релизной.
- Выгрузка YAML с правками применяет только ваши ручные правки из поля «Поля»; результаты ИИ-перевода надо копировать руками.
- Как и «Документы», доступ к связкам общий для всех редакторов.
