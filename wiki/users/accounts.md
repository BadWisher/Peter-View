# Учетные записи и роли

Эта страница описывает роли пользователей, работу администратора с учетными
записями и правила паролей. Она нужна администратору, который заводит
сотрудников, и пользователю, который меняет свой пароль или не понимает,
почему ему недоступен раздел **Настройки**. Здесь приведены две роли с
границами прав, порядок создания пользователя, выдача и смена пароля,
особенности учетных записей из OIDC и время жизни сессии.

Страница отвечает на вопросы: что может редактор и что может администратор,
куда девается пароль после создания учетной записи, почему после деплоя
приходится входить заново. Настройка OIDC-провайдера относится к
[**Implementation Guide**](../ops/deploy.md), страница [**Вход через OIDC**](../ops/oidc.md).

## Роли и границы прав

В сервисе две роли: **админ** и **редактор**. Разница касается только
изменения общего: пользователей, настроек модели, системного обзора,
редактирования гайдов и правил. Обычная работа, то есть проверки, выбор
гайда для себя, история и экспорт, доступна обеим ролям.

Матрица прав по основным действиям приведена в таблице ниже.

| Действие | Редактор | Админ |
|---|---|---|
| Запуск проверок, разбор, экспорт XLSX | да | да |
| Просмотр истории и аналитики | да | да |
| Выбор активного гайда для себя | да | да |
| Разделы под флагами: **Документы**, **Наблюдение**, **Спецификации API**, **Скриншоты** | да | да |
| Создание и редактирование гайдов, импорт из документов | нет | да |
| Глобальные правила-регулярки | просмотр | создание и удаление |
| Настройки модели и эмбеддингов | нет | да |
| Пользователи: создание, смена роли, удаление | нет | да |
| Раздел **Система**: диск, токены, журнал аудита | нет | да |
| Смена собственного пароля | да | да |

## Создание пользователя

Управление учетными записями ведет администратор в разделе **Пользователи**.
Пустой список с кнопкой добавления выглядит так.

  <figcaption>Раздел **Пользователи** до создания первой учетной записи.</figcaption>
</figure>

Порядок создания новой записи описан в шагах ниже.

1. Нажмите кнопку **Добавить**.
2. Укажите логин и выберите роль.
3. Задайте пароль или оставьте поле пустым. Если поле пустое, сервис
   генерирует пароль сам и покажет его один раз в следующем окне.

Сгенерированный пароль необходимо сразу передать сотруднику: повторно он не
показывается, доступен только сброс новым значением.

Удаление пользователя подтверждается отдельным окном с предупреждением о том,
что активные сессии удаляемой учетной записи завершатся. История проверок
удаленного пользователя остается в базе, но ни один другой пользователь не
получает к ней доступ.

Сервис запрещает два действия, защищающие от самопроизвольной потери
управления: нельзя удалить собственную учетную запись и нельзя снять роль
администратора с последнего администратора.

## Смена роли

Смена роли выполняется в таблице раздела **Пользователи** в колонке
**Доступ**. Изменение применяется мгновенно и не требует от пользователя
повторного входа.

## Пароли

Минимальная длина пароля составляет 8 символов. Проверка сложности не
выполняется: требования к цифрам и регистру остаются на совести пользователя
и политики, которую администратор доведет до команды.

Смена пароля завершает все прочие сессии этого аккаунта. Если пароль сменили
на рабочем компьютере, домашняя вкладка разлогинится при следующем запросе к
серверу.

При первом развертывании с пустой базой сервис автоматически создает учетную
запись с логином `admin` и паролем `admin`. Пароль необходимо сменить до
подключения других пользователей: пока он стандартный, любой, кто имеет доступ
к адресу сервиса, становится администратором.

## Учетные записи из OIDC

Если администратор включил вход через OIDC, на странице входа появляется
дополнительная кнопка корпоративного провайдера. Особенности таких учетных
записей перечислены ниже.

- У пользователя из OIDC нет локального пароля, и поле смены пароля для него
  скрыто.
- Роль администратора выдается автоматически, если в токене провайдера есть
  группа из настроенного списка администраторских групп. Остальные пользователи
  получают роль редактора.
- Учетные записи из OIDC помечены источником `oidc`, и локальный вход для них
  заблокирован: даже при правильно указанном прежнем пароле сервис ответит, что
  логин или пароль неверны.

Настройка провайдера, групп и отладка входа описаны в [**Implementation
Guide**](../ops/deploy.md) на странице [**Вход через OIDC**](../ops/oidc.md).

## Сессии

После входа браузер получает cookie-сессию сроком на 12 часов с продлением
при активности. Сессии хранятся в памяти процесса backend, поэтому
перезапуск сервера завершает их все: после деплоя обновления всем
пользователям нужно войти заново.

Неудачные попытки входа ограничены. Пять ошибок за 5 минут по паре «IP и
логин» дают ответ с кодом 429 и сообщением о слишком большом числе попыток и
необходимости подождать 5 минут. Счетчик ограничителя тоже хранится в памяти и
сбрасывается рестартом.
