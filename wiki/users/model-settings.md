# Настройки модели

Полноценная проверка (гайды, смыслы, согласованность) работает только с языковой моделью. Раздел «Настройки» доступен админам и настраивает два внешних сервиса: саму модель и эмбеддинги для поиска по длинным гайдам.

## Поля раздела «Модель»

| Поле | Смысл | Примечание |
|---|---|---|
| Адрес API | OpenAI-совместимый endpoint, например `https://api.openai.com/v1` | обязателен для LLM-проверок; без него они выключены |
| Модель | имя модели у провайдера | свободная строка, провайдер решит, знает её или нет |
| API-ключ | секрет | вводится один раз: поле показывает «Ключ задан», значение не отдаётся наружу и не затирается пустой отправкой |
| Температура | 0–2, шаг 0.1, по умолчанию 0 | для вычитки держите 0: правки должны быть воспроизводимы |
| Параллельность | 1–20, по умолчанию 3 в UI | сколько запросов к модели сервис шлёт одновременно |

## Поля раздела «Эмбеддинги»

Адрес API, модель, ключ. Нужны для гибридного подбора правил из длинных гайдов: короткие гайды (< примерно 30 правил) модель получает целиком, из длинных отбираются релевантные куски. Без эмбеддингов подбор деградирует до лексического по ключевым словам, работает хуже на объёмных сводах.

## Поля раздела «Выполнение»

| Поле | Смысл |
|---|---|
| Тайм-аут, секунд | 5–600, по умолчанию 120; сколько ждём один ответ модели |
| Усилие рассуждения | Низкое / Среднее / Высокое; параметр reasoning-моделей (для chat-моделей без reasoning игнорируется провайдером) |
| JSON-режим | просить у модели структурированный JSON ответ (response_format); с галочкой меньше сорванных разборов, но не все провайдеры это поддерживают |

## Кнопка «Проверить подключение»

Дёргает модель и эмбеддинги короткими запросами (по 30 секунд на сервис) и показывает результат по именам: «LLM: …», «Эмбеддинги: …». Ответ приходит 200 даже при неудаче, ошибка в тексте. Это первый инструмент диагностики: если проверки валятся на LLM-воркерах, начните с этой кнопки.

## Поведение при сохранении

- Пустые поля не отправляются, сохранённые значения остаются. Почистить адрес API или модель через UI нельзя (только вписать новый); секреты так и задумано, а вот `llm_base_url` придётся затирать через API: `PUT /api/settings` с явным `"llm_base_url": " "` не пройдёт валидацией схемы, но вписать `http://localhost` без ключа фактически выключит LLM (healthcheck не пройдёт).
- Настройки применяются на лету, клиентов к модели пересоздаёт подпиской, рестарт не нужен.
- Файл `data/llm_settings.json` пишется с правами 0600. Бэкап `data/` уносит ключи: храните архивы соответственно.

## Что видно в интерфейсе остальным

Обычные пользователи настроек не видят, но по поведению проверок замечают отсутствие модели: воркеры LLM помечаются ошибкой или пропуском, в отчёте появляется плашка о частичной проверке. Если команда жалуется на «пустые» отчёты по гайдам, проверяйте настройки первыми.

## Лимиты и стоимость

Каждая проверка с моделью жрёт токены: документ режется на чанки по 8 блоков с перекрытием в 2 блока (для больших документов размер чанка растёт, но их не бывает больше 24), каждый чанк проходит нужных воркеров, сверху верификатор. Полный расчёт по типовому документу на 50 тысяч знаков: десятки вызовов модели. Счёт токенов виден в «Аналитике» и «Системе». Если тариф провайдера маленький, снизьте параллельность и включите кэш запросов (он включён всегда: одинаковые «чанк + промпт» не уходят в модель повторно в течение жизни процесса).
