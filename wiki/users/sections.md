# Разделы по флагам: что включено и зачем

Помимо ядра (вычитка, гайды, история, аналитика), в сервисе четыре самостоятельных раздела. Каждый включается своей переменной окружения `FEATURE_*` и по умолчанию выключен, потому что нужен не всем командам и расширяет поверхность обращения наружу.

## Карта разделов

| Раздел | Флаг | Зачем нужен | Коротко |
|---|---|---|---|
| Документы | `FEATURE_DOCUMENTS` | централизованное хранилище проверяемых текстов | папки, версии, автоархив |
| API | `FEATURE_API` | контроль OpenAPI-спецификаций на двух языках | RU/EN связки, сегменты, ИИ-ревью диффа, автоперевод |
| Мониторинг | `FEATURE_WATCH` | следить за живыми страницами сайта | обход групп страниц по расписанию, диффы, снимки |
| Скриншоты | `FEATURE_SCREENSHOTS` | готовить картинки к публикации | холст: обрезать, замазать, подогнать ширину |

Документация каждого раздела: [Документы](documents.md), [API-спецификации](openapi.md), [Мониторинг](watch.md), [Редактор скриншотов](screenshots.md).

## Как включить

Только через `.env` на сервере, в интерфейсе тумблеров нет:

```text
FEATURE_DOCUMENTS=true
FEATURE_API=true
FEATURE_WATCH=true
FEATURE_SCREENSHOTS=true
```

После правки перезапустите стек (`./deploy.sh`). Выключенный раздел не показывается в меню, а его API отвечает 404 «Раздел недоступен» независимо от прав пользователя.

## Зачем такая скрытность

Мониторинг и вычитка по URL заставляют сервер ходить по адресам, которые указывают пользователи. Это вектор SSRF; механизмы защиты описаны в [архитектуре безопасности](../arch/security.md). Если вашей команде раздел не нужен, держите флаг выключенным: меньше surface, меньше вопросов от безопасников.
