# Фронтенд: SPA без сборки

Весь интерфейс `frontend/public/`: один HTML, семнадцать ES-модулей на 4306 строк, один CSS на 4513 строк. Ни Node, ни bundler, ни фреймворка. Правки подхватываются копированием в nginx-контейнер, сборочный шаг отсутствует как класс. Развёртывание nginx и CSP описаны в стеке ([Стек](../ops/stack.md)); карта модулей для ориентирования [Карта фронтенда](../arch/frontend-map.md), здесь конвенции и рабочие задачи.

## Загрузка и состояние

`index.html` (58 строк) фиксированный каркас: `#app` (единственная цель рендера, SPA заменяет innerHTML), `#overlay-root` для модалок, `#toast-root` для всплывающих сообщений, SVG-спрайт из 32 `<symbol>` (иконки вызываются хелпером `icon()` → `<use href="#...">`). Подключение ресурсов с руками заведёнными версионными query-строками: `style.css?v=52`, `js/app.js?v=52`, `tokens.css?v=48`. Любая правка требует поднять номер, иначе браузеры держат старый кэш; отдельной константы версии в коде нет.

`app.js` (77 строк) входная точка: грузит словарь `i18n/{ru,en}.json` (покрывает login, навигацию, аккаунт, часть админки; остальные строки зашиты по-русски в код), дергает `GET /api/auth/me`, при успехе грузит `/api/styleguides` и `/api/config` (оттуда актуальные `features`), ставит обработчик `hashchange` и рисует первый экран. При 401 рисует форму входа.

Состояние всеэкранное живёт в объекте `state` (`shared.js`, строки 57–94): пользователь, текущий маршрут, режим источника, flags проверок, текущий job и report, активные гайды, дерево репозитория, спецификации, `features`, тема. Это не стор с подписками: каждый экран читает и пишет напрямую, перерисовка после изменения состояния полная. Исключения точечные, DOM патчится напрямую там, где полная перерисовка убивает поток (стрим воркеров, бейдж мониторинга).

## Маршрутизация

Hash-роутинг, без History API. Таблица `renderers` в `router.js` (44 строки) сопоставляет хеш с `renderX()`: `#/check`, `#/review`, `#/documents`, `#/watch/<groupId>[/<pageId>]`, `#/api`, `#/guides`, `#/screenshots`, `#/history`, `#/insights`, `#/settings`, `#/users`, `#/health`.

Гварды сидят в `currentRoute()` (`shared.js`): `documents|watch|api|screenshots` проверяют флаг раздела и уводят на `#/check` при выключенном, три админских роута требуют `state.user.role === "admin"`, неизвестный путь падает в `check`. Это от UI-мусора; настоящая защита серверная (`feature_gate` + `require_admin`), обход через адресную строку упирается в 403/404.

Аргументы маршрута парсятся сегментами хеша (у watch до двух), query строка в хеше срезается. `renderApp()` перед каждым рендером снимает overlay, `inert` с `#app`, останавливает сторонние таймеры (опрос watch, слушатель вставки с клавиатуры) за исключением текущей цели.

## Конвенции кода

- Нативные ES-модули, только именованные `export function renderX/bindX`, никаких классов и default-экспортов.
- HTML собирается template literal'ами, вся подстановка пользовательских данных через `escapeHTML()`.
- Двойные кавычки, точки с запятой, camelCase; комментарии по-русски и объясняют «почему» (почему src у iframe, а не srcdoc; почему data: URL, а не blob:).
- После каждого `await` в асинхронном обработчике проверка `if (state.route !== ...) return`, чтобы ответ устаревшего запроса не нарисовался поверх нового экрана.
- Циклические импорты ломаются объектом `hooks` (`shared.js` держит ссылки `bindShell`/`renderApp`, которые назначает `app.js`) и ленивыми `import()`.
- Известные шероховатости, за которыми следите при ревью: `guides.js` в ветке ошибки обращается к `overlayRoot` и `app` без импорта, `documents.js` в preview-режиме вызывает неимпортированный `previewApi`.

## Слой доступа к API

Единственный вход в сеть хелпер `api(path, options)` (`shared.js:675`): `credentials:"same-origin"`, JSON-заголовок только если тело не `FormData` (иначе браузер сам ставит boundary), на `!ok` бросает `Error` с текстом `detail` и `.status`; бинарные ответы возвращаются как Blob по content-type. CSR-token не отправляется нигде, серверная защита origin-guard, фронт same-origin.

Ошибки показываются тостом `showError()` в `#toast-root` (автозакрытие 5 с, текст HTML-экранирован). Занятость кнопок через `setBusy(кнопка, флаг, подпись)`.

## Long-running UI: стрим джобы

Этот кусок (`check.js`, строки 470–554) стоит знания деталей, потому что только он не «запрос-ответ»:

- `EventSource("/api/jobs/{id}/stream", {withCredentials:true})` слушает `start` (новая карточка воркера), `delta` (текст в карточку), `end` (итог воркера, счётчик находок), `finished` (закрыть поток, забрать `GET /api/jobs/{id}/report`, уйти на `#/review`).
- Параллельно тикает поллинг `GET /api/jobs/{id}` раз в 1200 мс; если стрим открылся и потом оборвался, тост «Потеряна связь с сервером» и жизнь на одном поллинге.
- Дельты не перерисовывают DOM: имена dirty-воркеров копятся в `Set`, один `requestAnimationFrame` на фрейм дописывает `TextNode`'ы в `<pre>` карточки, автоскролл только если пользователь у нижнего края (48 px).

Кнопка «Отмена» чисто клиентская: закрывает слушатели, серверную задачу не убивает.

Разбор отчёта (`#/review`) принимает данные в любых прошлых форматах: `normalizedIssues()` перебирает алиасы полей (`line|line_number|block_index`, `message|description`, `fragment|match|span_text`, `recommendation|replacement|suggestion`, `engine|source`), severity режет по трём уровням, сортирует по блоку и позиции. Принять/отклонить замечание означает скрыть/показать (`state.hiddenIssues`), на сервер не пишется ничего; в xlsx уходят видимые строки (`POST /api/report-issues`).

## Опрос вместо стрима: watch

Мониторинг (`watch.js`, 865 строк) стрима не имеет: запуск группы `POST /api/watch/groups/{id}/run`, дальше `setInterval(renderWatch, 2000)` пока `group.running`; роутер снимает интервал при уходе с экрана. Копия страницы открывается iframe'ом на `GET /api/watch/pages/{id}/copy` (серверная HTML-копия со своим CSP, см. nginx), переключение «Было/Стало» меняет `src` на `?v=old`. Слияние текстовых хунков и UI-событий в человеческие фразы живёт на клиенте (`watchChanges`, `watchUiSentence`), сервер отдаёт сырые данные. Клик по строке изменения подсвечивает узел внутри iframe по `data-pvwatch-path`.

## Темы, i18n, доступность

Дизайн-токены в `tokens.css`: 12 зарегистрированных `@property` переменных (чтобы переключение темы анимировалось), светлая палитра `:root`, оверрайд `html[data-theme="dark"]`, обе темы в одних семантических именах (`--page, --surface, --ink, --primary...`). `theme-boot.js` (10 строк) до первой отрисовки читает `localStorage["pv-theme"]` и ставит атрибут, иначе вспыхнет белое. `style.css` использует только токены, сырые hex-цвета внутри компонентов не появляются.

Доступность по минимимуму, но осознанно: skip-link, `aria-live=polite` на тостах, `role=dialog` + `aria-modal` + focus trap + возврат фокуса в модалке, roving focus в меню аккаунта, клавиши `j/k/h` для навигации по замечаниям в разборе.

## Как добавить раздел

Полный проход на примере вымышленного `foo` (так же добавлялись documents, api, watch):

1. `backend/app/features.py` добавить `"foo"` в `OPTIONAL` и маппинг env `FEATURE_FOO`; новый `routers/foo.py` с `Depends(require_feature("foo"))` (плюс роль где надо); зарегистрировать роутер в `main.py`. Префикс пути для `feature_gate` middleware, если путь не начинается со стандартного.
2. `public/js/shared.js`: поле `state.foo`, запись в `routeMeta` (название и иконка), элемент в `navItems` или `adminItems`, `FEATURE_ROUTES.foo = "foo"`.
3. `public/js/foo.js`: `export async function renderFoo()` собирает HTML и вызывает `renderShell(...)`, плюс `bindFoo()` для обработчиков; все запросы через `api()`.
4. `public/js/router.js`: импорт и строка в `renderers`.
5. `public/index.html`: `<symbol>` новой иконки при необходимости; поднять `?v=` у изменённых css/js.
6. `public/style.css` на токенах; `i18n/ru.json` и `en.json` ключ `nav.foo`.
7. `nginx.conf` трогать не нужно, catch-all `/api/` проксирует новый путь; отдельный location требуется только для SSE или особых CSP.

## Preview-режим

`?preview=1` (или путь `/preview/`) включает демо-режим: выдуманный админ, все разделы включены, а `api()` перенаправляется в `previewApi()` regex-мок на 480 строк внутри `shared.js`, который выдаёт фикстуры и двигает статусы jobs/extract по номерам поллинга. Это живая витрина для GitHub Pages (`docs/preview/`) и песочница для вёрстки без сервера. Держать мок синхронным с реальным контрактом ничто не заставляет, обновляйте его руками при смене форм.
