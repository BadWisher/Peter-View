# Сборка этой вики

Исходники документации живут в `wiki/`, собираются MkDocs Material в статический сайт, публикуются на GitHub Pages по адресу `badwisher.github.io/Peter-View/wiki/`. Здесь цикл правок, правила навигации и перенаправления на старые адреса.

## Структура

| Путь | Что |
|---|---|
| `mkdocs.yml` | конфиг: `docs_dir: wiki`, тема Material, ru, палитра teal, плагины `search` и `redirects`, расширения `admonition`, `tables`, `toc` с permalink |
| `wiki/` | markdown-страницы: `index.md`, четыре раздела (`users/`, `arch/`, `dev/`, `ops/`), `screenshots/` (14 PNG интерфейса), `stylesheets/extra.css`, `javascripts/nav.js` |
| `docs/wiki/` | собранная вики, закоммичена как артефакт (в CI сборка идёт в `site/wiki`, коммит convenience для локального просмотра и истории) |
| `landing/`, `docs/preview/`, `docs/screenshots/` | лендинг Pages и демо-режим интерфейса, копируются в артефакт рядом с вики |

Навигация сайта задана секцией `nav` в `mkdocs.yml`, а не порядком файлов. Порядок разделов: Пользователям, Архитектура, Разработчикам, DevOps.

## Локальный цикл правок

```bash
pip install mkdocs-material
mkdocs serve          # http://127.0.0.1:8000, live-reload по wiki/
mkdocs build          # проверка ошибок сборки без поднятия сервера
```

Ссылки между страницами относительные, с суффиксом `.md` (`[Разбор](review.md)`, `[HTTP API](../dev/api.md)`): mkdocs сам перелинкует их в ЧПУ-адреса и упадёт с ошибкой на мёртвой ссылке. Картинки из `wiki/screenshots/` ссылками `screenshots/02-check.png` со страниц корня и `../screenshots/...` из подкаталогов.

После правок пересобранную копию в `docs/wiki/` обновлять не обязательно на каждый commit, CI собирает сайт с нуля из `wiki/` на push в `main` (workflow `pages.yml`: build через `mkdocs build --site-dir site/wiki`, затем копирование лендинга, шрифтов, превью и артефакт на Pages).

## Redirects на старые адреса

Структура вики менялась, внешние ссылки и закладки на старые пути не должны оставаться в пустоту. Плагин `redirects` в `mkdocs.yml` содержит ~45 правил вида `how-to/check.md: users/check.md` (включая додиатаксисные `quickstart.md`, `it.md`, `reference/*`). Правило: при переносе или переименовании страницы старое имя добавляете в `redirect_maps`, страницу-источник удаляете из `nav`.

## Согласованность с кодом

Документация врёт быстрее кода, поэтому держите привязки:

- Изменили маршрут, поле отчёта или формат xlsx правьте [HTTP API](api.md) в том же PR. Таблицы маршрутов этой страницы скопированы с исходников `routers/`, самый частый дрейф.
- Перевели раздел за флаг или сняли его правьте `users/sections.md`, `reference`-страницы ops и `nav`.
- Поменяли константу (лимит, TTL, батч) ищите число грепом по `wiki/`: цифры в тексте это тоже код.
- Скриншоты интерфейса после редизайна переснимаются в `wiki/screenshots/` под теми же именами; демо-режим для витрины `?preview=1` обновляется отдельно (`docs/preview/`).

## Голос и правила стиля текста

Вики пишется по тем же стандартам, что и интерфейс продукта, она сама проходит бы своей же проверкой.

- Русский язык, обращения на «вы» со строчной, активный залог, конкретика с числами и именами модулей вместо «значительно улучшено».
- Длинное тире `—` в тексте запрещено (то же правило, что для UI), где по смыслу нужно тире, ставится среднее `–`.
- Никаких «важно отметить», «давайте разберёмся», «в современном мире», «надёжное и масштабируемое решение» и прочих маркеров машинного текста; каждое предложение должно нести факт этого проекта, а не размытую воду, которая подойдёт любому продукту.
- Структура страницы по Diátaxis: одна страница один режим (обучение, инструкция, справка, объяснение). Смесь лечится переносом куска на свою страницу.
- Финальный блок любой страницы «Дальше» из 3–5 ссылок, без резюме-абзацев «В заключение».
